# uniswapv4-flow

Uniswap v4 위에 올라온 앱(훅 프로토콜)들이 **돈을 어떻게 움직이는지**를 흐름도 한 장으로 보여준다.
v4는 배포되면서 다양한 앱이 생겼지만 구조를 파악하기 어렵다 — 이 도구는 앱별 대표 트랜잭션을
골라 "이 앱은 스왑 한 번에 무슨 일을 벌이는가"를 그림으로 설명한다.

기존 익스플로러는 ERC20 `Transfer` 이벤트를 모아 흐름도를 그리는데, v4는 플래시 어카운팅이라
중간 단계에서 토큰이 실제로 움직이지 않는다. **훅이 값을 가져간 트랜잭션의 상당수는 Transfer
로그에 훅 주소가 아예 등장하지 않는다** — Unichain 표본 75%, Base 표본 67%. 그 격차를 메우는 게
이 도구다 ([spike/M0-FINDINGS.md](./spike/M0-FINDINGS.md)).

## 현재 상태

| 마일스톤 | 상태 |
|---|---|
| M0 — 트레이스 복원 검증 | ✅ 187/187 복원, 델타 제로 검증 |
| M1 — 단일 트랜잭션 렌더링 | ✅ 손으로 짠 SVG 레이아웃 |
| M2′ — 앱 카탈로그 | ✅ 트랜잭션 목록 → 앱 목록으로 재편 |
| M3 — 엔지니어 모드 | ✅ 회계 델타 오버레이 + 호출 트레이스 패널 |
| M5 — 다중 체인 | ✅ Unichain + Base |
| M4′ — 해시 직접 조회 | 보류 (유료 RPC 조달 결정 대기) |

**카탈로그**: 앱 11개 · 흐름(대표 tx) 20개 · 2개 체인. 모든 흐름은 델타 제로 불변식을 통과한다.
훅 신원은 [spike/known-hooks.json](./spike/known-hooks.json)에서 근거와 함께 수동 관리하고,
확인하지 못한 훅은 추측 없이 "Unidentified"로 정직하게 표시한다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
```

RPC는 필요 없다. 렌더링은 `src/fixtures/`의 정적 그래프 JSON만 읽는다 — 그래서 그대로 정적
호스팅에 올릴 수 있다.

**쓰는 법.** 상단 드롭다운에서 앱을 고르고(체인 드롭다운으로 Unichain/Base 전환), 왼쪽
사이드바에서 그 앱의 대표 흐름을 고른다. 다이어그램은 휠로 확대·축소, 드래그로 이동하며,
가운데 아래 "흐름 따라가기"로 정산을 순서대로 밟아 볼 수 있다. 우상단 **Trader / Engineer**
토글은 실제로 움직인 값만 볼지, 그 값을 설명하는 회계 델타까지 볼지를 바꾼다.

선택 상태는 전부 URL에 담긴다 — `?chain=`, `?app=`, `?flow=`, `?mode=engineer`, `?lang=ko`.
기본값이면 파라미터를 지워 링크를 깨끗하게 유지한다. 공유 링크는 보던 화면 그대로 열린다.

## 구조

```
src/
  types.ts        §7 데이터 모델 (Graph / AppEntry / FlowEntry)
  layout.ts       손으로 짠 노드 배치 + 엣지 라우팅(줄기 묶기) + 라벨 겹침 해소
  Diagram.tsx     SVG 렌더링 (다이어그램 라이브러리 없음) + 줌/팬 + 흐름 따라가기
  TracePanel.tsx  엔지니어 모드 호출 트레이스 패널 (다이어그램과 양방향 하이라이트)
  trace.ts        unlock() 안의 장부 기록을 실행 순서로 재구성
  format.ts       금액/주소/훅 권한 표기
  i18n.ts         KR/EN 사전과 ?lang= 처리 (기본 EN)
  App.tsx         상단 바(앱·체인 드롭다운, 모드·언어 토글) + 사이드바 인스펙터
  fixtures/       흐름 20건 + apps.json (앱 카탈로그)
spike/            트레이스 복원 엔진과 검증 하네스, 데이터 파이프라인
```

데이터는 `spike/`가 만든다. 트레이스를 복원해(`reconstruct.mjs`) §7 모델로 바꾸고(`graph.mjs`)
토큰 심볼을 붙여 정적 JSON으로 굽는다(`build-fixtures.mjs`). 훅 레지스트리는 코퍼스에서
뽑고(`build-hook-registry.mjs`) 신원을 `known-hooks.json`에 매핑한다. 자세한 내용은
[spike/README.md](./spike/README.md).

## 엣지 층

같은 값을 두 번 세지 않도록 엣지를 두 층으로 나눈다.

- **settlement** — 실제로 움직인 값 (`settle`/`take`/`mint`/`burn`). Trader 모드가 그리는 층.
- **accounting** — 그 값을 설명하는 채무 (swap 델타, 훅 몫). Engineer 모드에서 덧씌운다.

두 층은 같은 값을 장부 반대편에서 본 것이라, 섞어 그리면 금액이 두 배로 보인다.
세 번째 층 **reach**(훅 → 외부 컨트랙트 호출)는 금액이 없는 관계선으로, 점선으로 구분한다.

## 안 하는 것

수익률·추천·위험 판정을 하지 않는다. MEV 패턴도 분류하지 않는다.
"이 트랜잭션에서 이런 일이 있었다"는 사실 서술만 한다.
